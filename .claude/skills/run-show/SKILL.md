# 展示を動かす

利用者は非エンジニア。手順は短く、結果だけを伝える。

## 起動の準備を手伝う

1. `docs/run-windows.md` の手順どおりに案内する。利用者のパソコンで打つコマンドは1つずつ示す
2. API の鍵はファイルにもこの会話にも書かせない。PowerShell の `$env:ANTHROPIC_API_KEY` で設定してもらう
3. うまく動かないときは「困ったとき」の節から当てはまるものを1つ選んで伝える

## 振り返る（自分で直す仕組み）

1. `npm run review [日付]` を流す（日付を省くと最新の日）
2. 出てきた `docs/agent/改善記録/<日付>.md` を読み、「よく効いた場面・効かなかった場面・次に試すこと」を3行で伝える
3. 「次に試すこと」のうち、決まり（`shared/scene.mjs` の範囲）の中で直せるもの（例: 場面ごとの色・速さ・キーワード）は、そのまま直して `npm test` を流し、何を変えたかを同じ改善記録の末尾に足す
4. 頭脳への指示（`server/brain.mjs` の SYSTEM_PROMPT）を直したら、`config/notes.md` に「何を・なぜ変えたか」を1行足す（次の展示で頭脳が読む）
5. Google Drive にまとめを残すときは、置き場所のフォルダを利用者に確かめてからにする。作ったら同じ中身を `docs/drive/<ファイル名>/` にも残す

## 場面を変える・増やす

1. 場面の決まりは `shared/scene.mjs` の1か所だけ。名前・範囲・キーワードはそこで直す
2. 新しい動きを足すときは `stage/index.html` の描画（`S.form===` の並び）に1つ足し、`FORMS` に名前を足す
3. `npm test` が通ることを確かめてから、利用者に試してもらう

## 良い結果の基準

- 命令は必ず決まった形に収まる（場面5種・色3つ・範囲内の数・返事30字以内）
- 言葉の気分と場面が合う／同じ場面を3回続けない／人がいないときは静かな場面で返事なし
- エージェントの答えは10秒以内。失敗してもキーワードで動き続ける

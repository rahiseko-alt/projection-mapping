# 展示を動かす

利用者は非エンジニア。手順は短く、結果だけを伝える。

## 起動の準備を手伝う

1. `docs/run-windows.md` の手順どおりに案内する。利用者のパソコンで打つコマンドは1つずつ示す
2. API の鍵はファイルにもこの会話にも書かせない。PowerShell の `$env:ANTHROPIC_API_KEY` で設定してもらう
3. うまく動かないときは「困ったとき」の節から当てはまるものを1つ選んで伝える

## 自動で動かす

1. `docs/run-windows.md` の「展示を自動で動かす」どおりに、`config/show.json`（時間割・プロジェクターの位置）を一緒に作る
2. `show.bat` で起動、`autostart-on.bat` でサインイン時に自動で始まる。閉まる時刻に自動で振り返る

## 振り返る（自分で直す仕組み）

1. `npm run review [日付]` を流す（日付を省くと最新の日）。振り返り役のエージェントが、場面の設定（`config/presets.json`）と頭脳への改善メモ（`config/notes.md`）を自分で直す
2. 出てきた `docs/agent/改善記録/<日付>.md` を読み、「よく効いた場面・直したこと・次に試すこと」を3行で伝える
3. 決まりの外の直し（新しい場面・頭脳への指示 `server/brain.mjs` の SYSTEM_PROMPT）が要りそうなら、直して `npm test` を流し、何を・なぜ変えたかを同じ改善記録の末尾と `config/notes.md` に足す
4. 直した設定が悪かったときは `config/presets.json` を消せば元に戻る
5. Google Drive にまとめを残すときは、置き場所のフォルダを利用者に確かめてからにする。作ったら同じ中身を `docs/drive/<ファイル名>/` にも残す

## 場面を変える・増やす

1. 新しい場面は、利用者の言葉をそのまま渡して `npm run create -- "<利用者の言葉>"` を流す。場面づくり役のエージェントが動きを書き、自動の試し動かしを通ったものだけが `config/forms/` に入る
2. できたら名前とキーワードを伝え、`npm start` し直して試してもらう。合わなければ `config/forms/<id>.json` を消す
3. 場面の音は、元の5つは `shared/sound.mjs` の BUILTIN_SOUNDS、新しい場面は `config/forms/<id>.json` の sound（base・wave・bright・pulse・scale）で直す
4. 元からある5つの場面の決まり（名前・範囲・キーワード）は `shared/scene.mjs`、動きは `shared/forms.mjs`。直したら `npm test` を流す

## 背景の動画・画像

1. 利用者の素材を `media/<場面のid>/`（全場面なら `media/all/`）に置くよう案内する。使える種類は mp4・webm・mov・jpg・png・webp・gif、1つ500MBまで
2. 素材は GitHub に上げない（`.gitignore` 済み）。利用者の素材を勝手に探したり開いたりしない

## 良い結果の基準

- 命令は必ず決まった形に収まる（場面5種・色3つ・範囲内の数・返事30字以内）
- 言葉の気分と場面が合う／同じ場面を3回続けない／人がいないときは静かな場面で返事なし
- エージェントの答えは10秒以内。失敗してもキーワードで動き続ける

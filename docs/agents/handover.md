## 2026-11-25 背景の動画・画像と、PC で試しやすくする仕組み

**決めたこと**

- 背景は `media/<場面>/`（共通は `media/all/`）に入れた動画・画像を、場面が変わるたびに2秒で切り替える。素材は GitHub に上げない
- `start.bat`・`review.bat` をダブルクリックで動かす。カメラを起動する前は、マウスや指が手の代わり
- クラウドの GPU は、まず手元だけで確実に動かしてから、AI で描いた背景を上乗せする役として検討する（利用者と合意）

**次にやること**

- 利用者が帰宅後、PC で `start.bat` から試す（マウス → カメラ → プロジェクター → 音 → 背景の順）
- 残りは「展示の自動運転」。PC の Claude アプリを最新にすれば、この会話から PC につなげるかもしれない（未確認）

**未解決の問題**

- 動画は再生と中身まで確認したが、試しの環境の画面写しには写らなかった（実機で見て確かめる）

## 2026-11-25 場面ごとの音を追加

**決めたこと**

- 音はブラウザの音の機能（Web Audio）だけで作る。素材のファイルは使わない。場面ごとの響き・手を握ると鈴・人が増えると少し大きく
- 新しい場面の音は場面づくり役が一緒に決める（範囲に収めて保存）。オーロラには手で音を付けた

**次にやること**

- 利用者の Windows とスピーカーで、音の大きさと響きを確かめる（鈴はカメラで手を握ったときだけ鳴るので、ここでは未確認）
- 残りの仕事は「動画・画像を映す」「展示の自動運転」（易しい順）

**未解決の問題**

- 響きの好みは人による。気に入らない場面があれば sound の値を直す

## 2026-11-25 場面づくり役のエージェントを追加

**決めたこと**

- 新しい場面は `npm run create -- "<頼み>"` でエージェントが作る。動きは決まった形の関数の中身だけ（Math と引数のみ。for・while・文字列・[ ] などは不可）。保存の前に試し動かし（止まらない・壊れない・重くない・画面に残る・固まらない）を通す。5回まで直させる
- 作った場面は `config/forms/<id>.json`。受付役・頭脳・映像の本体の全部が起動時に読み、同じ確かめ方を通す。最初の1つ「オーロラ」を入れた

**次にやること**

- 利用者の Windows で、オーロラを含めた場面を実機で見る
- 次に任せたい仕事（音・動画や画像・自動運転）は、利用者が選んだ順に進める

**未解決の問題**

- 作った場面の見た目の良し悪しは自動では測れない（見た人の反応は振り返り役が測る）

## 2026-11-25 振り返り役のエージェントを追加

**決めたこと**

- 展示の後の振り返りもエージェントに任せる（`npm run review`）。道具は場面の設定を直す・頭脳への改善メモ・改善記録の3つ。1回5か所まで、根拠（数字）つき。前→後と理由は道具の側で必ず記録する
- 直した設定は `config/presets.json`（消せば元に戻る）。頭脳は Claude Code のログインで動く（鍵は要らない）

**次にやること**

- 利用者の Windows で起動し、実機（カメラ・投影・四隅の補正・ログイン）を確かめる
- 実際の展示の記録で `npm run review` を流し、直し方が妥当かを見る

**未解決の問題**

- 個人で使う範囲でログインを使ってよいかの規約上の確証は無い
- MapMap の命令の書き方（2通り）と、CPU での滑らかさは実機で未確認

## 2026-11-25 意思を持つ光 0.1.0（投影・受付役・エージェント・自分で直す仕組み）

**決めたこと**

- Windows・CPU だけで動かす。映像の本体は Chrome 全画面（MediaPipe・Maptastic）、受付役は Node.js、頭脳は Claude Agent SDK（道具は場面を出す1つだけ）。Ollama・StreamDiffusion は使わない

**次にやること**

- 頭脳は Claude Code のログインで動くことを作業環境で確認済み（鍵なし）。利用者の Windows でもログインで動くかを確かめる
- 展示の振り返りを Google Drive にも残すなら、置き場所のフォルダを利用者に確かめる

**未解決の問題**
